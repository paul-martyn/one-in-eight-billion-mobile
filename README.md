# One in Eight Billion — мобильная веб-версия

Отдельный проект интерфейса для будущего портирования One in Eight Billion в Unity. На текущем этапе создана только основа веб-приложения: один нейтральный экран `FoundationScreen` с демонстрационными данными. Карта экранов будет добавлена после получения макетов.

Игровая логика зафиксирована по восстановленной публичной версии **1in8b.life 0.8.98 beta от 31 октября 2026 года**. Она сохранена как справочный снимок и **не импортируется и не исполняется** новым приложением. Демонстрационные данные не являются результатом текущей симуляции.

## Запуск

Стек: React 19.3.1, TypeScript 7.0.2, Vite 8.3.5. Для проекта выбран Node.js 24.16.0; точные зависимости закреплены в `package-lock.json`.

```powershell
npm ci
npm run dev
```

Адрес разработки: <http://127.0.0.1:4190/>.

| Команда | Назначение |
|---|---|
| `npm run dev` | Сервер разработки на `127.0.0.1:4190` |
| `npm run build` | Проверка снимка оригинала, проверка TypeScript и сборка Vite |
| `npm run preview` | Просмотр готовой сборки на `127.0.0.1:4191` |
| `npm run check` | Проверка снимка, типов и тестов |
| `npm test` | Тесты через встроенный Node.js test runner |
| `npm run verify:core` | Проверка сохранённых файлов оригинала по манифесту |

Это самостоятельный локальный Git-репозиторий. Удалённый репозиторий и публикация приложения не настроены.

## Ограничения интерфейса

- Вся композиция приложения рассчитана исключительно на портретный экран. Базовый макет — **393 × 852** CSS-пикселя.
- На телефонах шириной 320–430 CSS-пикселей интерфейс адаптируется к доступному месту; на широком экране сохраняется та же портретная рамка.
- На сенсорном устройстве в альбомной ориентации показывается просьба повернуть устройство. Программная клавиатура не должна ошибочно включать этот режим.
- Поворот устройства не должен размонтировать приложение и сбрасывать состояние.
- Сейчас нет игровых кнопок, таймеров, симуляции или переходов между будущими экранами. Оформление этого экрана не задаёт будущую карту экранов.

Веб-приложение управляет собственной композицией и сообщением об ориентации; физическая блокировка поворота браузера не является гарантированной возможностью веб-платформы.

## Карта проекта

| Путь | Назначение |
|---|---|
| `src/app/` | Запуск приложения и портретная оболочка |
| `src/screens/` | Экраны; сейчас только `FoundationScreen` |
| `src/components/` | Общие компоненты отображения |
| `src/fixtures/` | Демонстрационные данные для макетов |
| `src/contracts/` | Типы данных представления и интерфейсных действий |
| `src/adapters/` | Документированная граница будущего подключения симуляции; рабочего адаптера пока нет |
| `reference/original-0.8.98/` | Неизменённые восстановленные файлы, таблицы, синтетические примеры, лицензии и индексы оригинала |
| `reference/provenance.json` | Происхождение снимка и перечень файлов с размером и SHA-256 |
| `docs/architecture.md` | Границы интерфейса, данных и будущей симуляции; порядок подключения экранов |
| `AGENTS.md` | Правила работы с этим репозиторием |

Снимок содержит шесть читаемых исходных JS-файлов и шесть соответствующих оригинальных сборок, 210 извлечённых наборов данных и пять файлов примеров. Всего с индексами и лицензиями — 239 файлов. Извлечённые JSON — справочная копия таблиц; оригинальная игра использует таблицы, встроенные в опубликованную сборку. Примеры синтетические, личных сохранений нет. Сведения о лицензиях сохранены рядом с исходными материалами; создание этого репозитория не меняет их условий.

Это выбранная часть восстановленного проекта, достаточная как эталон логики и данных. Полный сайт со всеми локалями, шрифтами и страницами остаётся в прежней папке восстановления. Никаких ссылок на соседние папки для обычного запуска этого репозитория не требуется.

## Следующий этап

После получения карты экранов сначала создаём экраны на демонстрационных данных. Затем подключаем их по одному через адаптер и данные представления, проверяя соответствие оригинальной симуляции. Формулы, баланс, условия событий и последовательность случайных выборов не переносятся в React-компоненты.

Восстановленная сборка объединяет игру, DOM-интерфейс, хранение и сетевые функции; она пока не является независимым движком. Серверные исходники и пользовательская база не восстановлены. Социальные функции, облачные сохранения и покупки не работают в этом каркасе.

Будущий Unity-порт потребует отдельной реализации и проверки поведения. Текущая структура помогает отделить отображение от правил, но не выполняет автоматическое преобразование JavaScript в C#.

Основания выбора инструментов: [React о создании SPA с Vite](https://react.dev/learn/build-a-react-app-from-scratch), [руководство Vite](https://vite.dev/guide/). Ограничения браузерной ориентации описаны в [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/orientation). Manifest добавлен, но полноценный offline/PWA-режим пока не реализован.
