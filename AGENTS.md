# Экспериментальная самостоятельная версия

Этот каталог — отдельный эксперимент One in Eight Billion Independent. Рабочая мобильная версия находится в соседнем `../one-in-eight-billion-mobile/`; не изменяйте её файлы, настройки, сохранения, сборку или Git в рамках этого эксперимента.

## Движок и интерфейс

- Самостоятельный игровой движок размещается в `src/engine/`. Приложение должно запускаться и собираться из собственных исходников без папок recovery/reference, без генерации core из оригинала и без доступа к оригинальному сайту.
- Эксперимент сохраняет тот же мобильный интерфейс: портретная композиция 393 × 852, ширины телефона 320–430 CSS-пикселей и портретная рамка на desktop. Перенос интерфейса сам по себе не меняет игровой flow.
- `src/core/` содержит контролируемое окружение, часы, поток случайности и хост движка; `src/adapters/` связывает его с UI. Экраны, React-компоненты и flow читают view models и отправляют команды через адаптер. Не создавайте вторую изменяемую копию игрового состояния в UI.
- Сохраняйте формулы, баланс, вероятности, порядок RNG, правила времени, условия событий и формат сохранений. Отрисовка, анимации и смена ориентации не расходуют игровой RNG и не продвигают время.
- Сохраняйте совместимость `one8b.*`, префикса `1in8b-mobile/v1:` и формата `{S, at}`. Переименование ключей требует явной миграции. Отдельный порт разработки изолирует хранилище этого эксперимента от мобильной версии.
- Оригинальный сервер, статистика, облако, покупки и старый интерфейс не подключаются. Отсутствующие сервисы не заменяются фиктивным успехом.

## Проверки и происхождение

- Дизайн-токены — `src/design/tokens.json` и `motion.json`; `npm run tokens` генерирует из них `src/design/tokens.css` (руками не правится, те же имена переменных — в `tokens.uss` Unity-порта). В CSS цвета, кегль, длительности и кривые пишутся через `var(--…)` (кегль — шкала `--font-size-label/small/body/…`: подписи от 12, вторичный текст от 14, основной от 16); `npm run check:tokens` (входит в `npm run check`) проверяет свежесть `tokens.css` и не даёт добавлять литералы сверх `tools/design/literals-baseline.json`. Убрали литералы — обновите базовую линию: `npm run check:tokens -- --update`.
- Контраст: пары «текст — фон» перечислены в `tokens.json` → `contrast.pairs`; `npm run check:tokens` падает, если пара ниже 4,5 : 1 (крупный текст и фокус — 3 : 1). Новый цвет текста — новая пара.
- Совместимость с USS Unity: `npm run lint:uss` (входит в `npm run check`) не даёт добавлять в CSS то, чего нет в USS (grid, псевдоэлементы, `box-shadow`, `@keyframes`, `calc()`, `vh`/`cq`/`em`, `z-index`, селекторы атрибутов и т. п.), сверх `tools/design/uss-baseline.json`. Файлы нового дизайна проверяются строго: `npm run lint:uss -- путь/к/файлу.css`. Блокеров стало меньше — `npm run lint:uss -- --update`.
- Экраны нового флоу (план — `../mobile-mockups/production-ui/INTEGRATION-PLAN.md`) рисуются в кадре макета 393 × H: `Frame` из `src/ui/frame`, места по высоте — `src/screens/layouts.ts`; размеры в CSS таких экранов — в единицах кадра (px макета), без `cqh`/`clamp`. Под экранами Language, Start и Hub — одна общая планета (`src/flow/PlanetStage.tsx`, логика — `src/ui/planet/planetCore.js`); экран над ней — `pscreen over-planet`, без своей «бумаги». Для этих файлов `lint:uss` не строгий: после добавления нового экрана обновите базовые линии (`npm run check:tokens -- --update`, `npm run lint:uss -- --update`).
- «Назад» (Esc, в Unity — ещё и системная кнопка Android): обработчики регистрируются через `useBack` из `src/flow/useBack.ts` слоями `dialog` → `screen` → `flow` (окно закрывается безопасным действием, вкладка жизни → «Жизнь», «Жизнь» → пауза, экран поверх → pop). Свои слушатели `keydown` для Escape не добавляйте.
- Прогон экранов: `npm run shots` проходит весь флоу в Chrome (`playwright-core`, свой dev-сервер), снимает кадры 390×844 и 1920×1080 в `artifacts/ui-shots/<дата>/` и пишет `report.md`: текст мельче 12 px, разорванные слова, обрезка многоточием, подозрение на низкий контраст. Языки — `--lang ru,de`, строгий режим — `--strict`; жизнь одна и та же благодаря `--seed`.
- `npm run dev` использует порт 4192, `npm run preview` — 4193. `npm run build` проверяет типы и собирает собственные исходники; подготовительный запуск извлечения из оригинала не требуется.
- Сценарии самостоятельного движка должны проверять существенное поведение: результаты команд, RNG, время, сохранение и восстановление. Отдельные инструменты сверки с историческим эталоном допустимы для разработки, но не должны становиться обязательной зависимостью запуска или сборки.
- `docs/scaffold-import-manifest.json` фиксирует каждый скопированный файл, исходный путь, размер и SHA-256 до интеграционных изменений. Не переписывайте исходные хеши для сокрытия последующих изменений.
- Сохраняйте уведомления об авторстве и лицензиях, `public/licenses/`, `licenses/`, а также метаданные происхождения ресурсов. Удаление технических зависимостей от оригинального сайта не означает удаления правовых уведомлений.
- Не добавляйте личные сохранения, ключи, токены, пароли, браузерные профили, `node_modules`, `dist` или временные артефакты в Git.

## Обнаружение кода

Для исследования кода предпочитайте codebase-memory-mcp: `search_graph`, `trace_path`, `get_code_snippet`, `query_graph`, `get_architecture`. Если отдельный эксперимент ещё не индексирован, сначала вызовите `index_repository` для его каталога. Для строковых литералов, конфигураций и пробелов индекса допустим `rg`. Недоступность графа не блокирует локальную работу.
