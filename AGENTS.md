# Правила проекта

## Текущий этап

Этот репозиторий содержит основу мобильного веб-интерфейса One in Eight Billion. Пользователь предоставит карту экранов позже. До этого не придумывайте полный экранный поток, дизайн-документ, игровые действия или механику навигации. Единственный текущий экран — нейтральный `FoundationScreen`, использующий явно обозначенные демонстрационные данные.

## Неизменность оригинала

- `reference/original-0.8.98/` — неизменяемый снимок восстановленной публичной версии 0.8.98 beta от 31 октября 2026 года. Не форматируйте, не исправляйте и не редактируйте его файлы.
- `reference/provenance.json` фиксирует происхождение, пути, размеры и SHA-256. Не обновляйте контрольные суммы для сокрытия изменений снимка. Для новой версии создавайте новый отдельный снимок с документированным происхождением.
- Не импортируйте и не исполняйте код из `reference/` в приложении. Это сцепленная браузерная сборка, а не готовый независимый SDK.
- Не добавляйте личные сохранения, пароли, токены, ключи, браузерные профили или `node_modules` в Git.
- Не меняйте формулы, вероятности, баланс, условия событий, порядок RNG и формат сохранений без отдельного явного указания пользователя.

## Границы реализации

- `src/app/`, `src/screens/`, `src/components/` отвечают за интерфейс.
- `src/fixtures/` содержит только демонстрационные данные для макетов; явно отличайте их от состояния симуляции.
- `src/contracts/` описывает данные представления и действия интерфейса; не связывайте React-компоненты напрямую с глобальным состоянием `S` оригинала.
- `src/adapters/` пока содержит только описание будущего подключения. Не подключайте рабочий движок до соответствующего этапа задачи.
- При последующей интеграции подключайте экраны по одному: действие интерфейса → адаптер → оригинальная логика → данные представления → экран. Не дублируйте игровые формулы в UI.
- До переноса в Unity проверяйте воспроизводимость seed/RNG, времени, решений и сохранений по эталонным сценариям. Не обещайте автоматическую конвертацию в C#.

## Портретный интерфейс

- Вся композиция — исключительно портретная; базовый макет 393 × 852 CSS-пикселя.
- Поддерживайте ширины телефона 320–430 CSS-пикселей. На desktop сохраняйте ту же портретную рамку, без отдельной широкой компоновки.
- На сенсорном устройстве в альбомной ориентации показывайте просьбу повернуть устройство. Не определяйте ориентацию только по уменьшившейся высоте viewport: открытие клавиатуры не должно включать это сообщение.
- Смена ориентации не должна размонтировать приложение или терять состояние.
- Проверяйте читаемость, прокрутку и доступность элементов на узком экране; учитывайте безопасные области устройства.

## Проверки

Используйте `npm run check` и `npm run build` для проверки законченных изменений. `verify:core` должен подтверждать неизменность снимка. Добавляйте тесты только там, где они проверяют существенное поведение; не имитируйте реализацию в тесте. Не ослабляйте проверку снимка, чтобы получить успешную сборку.

## Codebase Knowledge Graph (codebase-memory-mcp)

Для обнаружения кода всегда предпочитайте MCP-граф grep/glob/поиску файлов. Если этот отдельный репозиторий ещё не индексирован, сначала вызовите `index_repository` для его корня.

Порядок инструментов:

1. `search_graph` — поиск функций, классов, маршрутов и переменных по шаблону.
2. `trace_path` — кто вызывает символ и что вызывает он.
3. `get_code_snippet` — исходный код конкретного символа.
4. `query_graph` — сложные связи и многошаговые запросы.
5. `get_architecture` — общая архитектура проекта.

Используйте `search_code` или `rg` для строковых литералов, сообщений, конфигураций, неисполняемых документов и пробелов в индексе. Если граф не дал достаточного результата, допустим обычный поиск; не выдавайте отсутствие символа в графе за доказательство отсутствия кода.
