# Правила проекта

## Текущий этап — интеграция (с 1 ноября 2026)

Новый интерфейс One in Eight Billion подключается к оригинальной игровой логике 0.8.98. Экраны берутся из холста дизайна (`design/claude-canvas/`, страница «Production»); недостающие экраны и состояния сначала согласуются с пользователем, затем рисуются в том же стиле. Прежнее ограничение «только fixtures, core не подключать» относилось к подготовке каркаса и больше не действует.

## Эталон и производный core

- `reference/original-0.8.98/` — неизменяемый снимок восстановленной публичной версии 0.8.98 beta от 31 октября 2026 года. Не форматируйте, не исправляйте и не редактируйте его файлы.
- `reference/provenance.json` фиксирует происхождение, пути, размеры и SHA-256. Не обновляйте контрольные суммы для сокрытия изменений снимка. Для новой версии создавайте новый отдельный снимок с документированным происхождением.
- Приложение исполняет **производный core** `src/core/generated/`, который `tools/core/extract-core.mjs` воспроизводимо получает из эталона: тело сборки не меняется, добавляется только обёртка `instantiateCore(env)`, связывающая каждое свободное имя с контролируемым окружением (`src/core/env.ts`). Сгенерированные файлы не редактируются вручную и не хранятся в Git. Любой новый технический патч описывается в `docs/core-derivation.md` с причиной и проверкой.
- Старый интерфейс оригинала не запускается и не подключается через iframe. Обработчики старого UI, которые меняют состояние игры, повторяются в адаптере тем же порядком вызовов оригинальных функций и сверяются с исходным обработчиком в тестах.
- Не меняйте формулы, вероятности, баланс, условия событий, порядок RNG, правила времени и формат сохранений. Анимации, рендеры, StrictMode, панели и поворот экрана не расходуют игровой RNG и не двигают игровое время.
- Не добавляйте личные сохранения, пароли, токены, ключи, браузерные профили или `node_modules` в Git.

## Границы реализации

- `src/app/`, `src/flow/`, `src/screens/`, `src/ui/` — интерфейс. Они получают read-only view models и отправляют типизированные команды только через `src/adapters/`; прямой импорт `src/core/*` из UI запрещён (проверяет `verify:core`).
- `src/core/` — хост производного core: окружение, поток случайности, загрузка. Единственный владелец игрового состояния — core; вторую изменяемую копию персонажа в React/flow не создавать.
- `src/adapters/` — команды (ровно однократное применение), игровые часы, view models. Условия доступности, цены, риски и тексты берутся из оригинальных функций; компоненты их не пересчитывают.
- `src/adapters/meta.ts` и `src/adapters/vm/rewards.ts` — мобильная мета-экономика (энергия, доллары, кристаллы, награда за жизнь) по решению продукта от 1 ноября 2026. Она только читает итог жизни из core и не меняет `S`, сохранение жизни и поток случайности; параметры (`META_RULES`, `REWARD_RULES`) ждут утверждения.
- `src/fixtures/` — только для изолированного просмотра макетов. В игровом запуске при сбое адаптера показывается честная ошибка, а не демонстрационные числа.
- Сеть оригинала (статистика, облако, покупки, деревни) отключена в окружении core. Для таких функций показываются состояния «недоступно», а не имитация успеха.
- Эквивалентность производного core и оригинала проверяют `tests/core/` (оригинал в `node:vm` против производного core на одинаковых seed, часах и командах). До переноса в Unity сохраняйте эти сценарии и спецификации; не обещайте автоматическую конвертацию в C#.

## Портретный интерфейс

- Вся композиция — исключительно портретная; базовый макет 393 × 852 CSS-пикселя.
- Поддерживайте ширины телефона 320–430 CSS-пикселей. На desktop сохраняйте ту же портретную рамку, без отдельной широкой компоновки.
- На сенсорном устройстве в альбомной ориентации показывайте просьбу повернуть устройство. Не определяйте ориентацию только по уменьшившейся высоте viewport: открытие клавиатуры не должно включать это сообщение.
- Смена ориентации не должна размонтировать приложение или терять состояние.
- Проверяйте читаемость, прокрутку и доступность элементов на узком экране; учитывайте безопасные области устройства.

## Проверки

Используйте `npm run check` и `npm run build` для проверки законченных изменений. `verify:core` подтверждает неизменность снимка и границы UI; `npm run test:equivalence` — поведение производного core. «Эталон не изменился» и «core ведёт себя так же» — разные проверки, нужны обе. Добавляйте тесты только там, где они проверяют существенное поведение; не имитируйте реализацию в тесте. Не ослабляйте проверку снимка и не нормализуйте игровые расхождения ради зелёного теста.

## Codebase Knowledge Graph (codebase-memory-mcp)

Для обнаружения кода всегда предпочитайте MCP-граф grep/glob/поиску файлов. Если этот отдельный репозиторий ещё не индексирован, сначала вызовите `index_repository` для его корня.

Порядок инструментов:

1. `search_graph` — поиск функций, классов, маршрутов и переменных по шаблону.
2. `trace_path` — кто вызывает символ и что вызывает он.
3. `get_code_snippet` — исходный код конкретного символа.
4. `query_graph` — сложные связи и многошаговые запросы.
5. `get_architecture` — общая архитектура проекта.

Используйте `search_code` или `rg` для строковых литералов, сообщений, конфигураций, неисполняемых документов и пробелов в индексе. Если граф не дал достаточного результата, допустим обычный поиск; не выдавайте отсутствие символа в графе за доказательство отсутствия кода.
