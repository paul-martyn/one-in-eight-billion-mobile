# Остаточные ссылки и самостоятельность приложения

Проверено 2 ноября 2026 года. Название продукта «One in Eight Billion» сохраняется по решению пользователя. Цель очистки — самостоятельная работа приложения и актуальная документация о его устройстве.

## Исполняемые зависимости

Движок импортируется из локальных `src/engine/game.<lang>.js`, `era.js` и `state-effects.js`. В `src`/`public` и production-модулях проверяются отсутствие исходного домена, старых `/api/`, скриптов keepx/labw и Umami, удалённых модулей и импортов в reference/raw/generated/recovery. Генерации core при запуске, проверке и сборке нет. Для `check`, `build`, `verify:build` не нужны архивы или соседние приложения.

Проверка `tools/engine-boundaries.mjs` анализирует модульные импорты и локальные ресурсы. Она запускается до сборки и для каждого исполняемого production-модуля после сборки. Попытки сетевого вызова в контролируемом окружении не исполняются и фиксируются локально. Сама игра не подключена к оригинальному серверу.

Обычные npm-зависимости — React, React DOM, Motion и четыре пакета шрифтов; инструментальные зависимости — TypeScript, Vite, React plugin, типы и Acorn. Отдельного npm-пакета оригинального игрового core среди них нет.

## Дополнительная очистка текстов

Из каждой из пяти таблиц `I18N_T` удалены 233 неиспользуемых записи о старых сервисах: сообщество, публичные мемориалы, оплата, облако, поддержка, лаборатория и распространение старой страницы. Итого 1 165 записей. Перед удалением проверены ссылки на ключи, хеши строк/шаблонов и переопределения переводов в движках, адаптере и UI. Используемые игровые переводы сохраняются. Детальный список и SHA-256 до/после находятся в `legacy-text-cleanup.json`; защитная проверка запрещает возврат удалённых ключей.

Исторический шаблон свидетельства о смерти использует адаптер для двух игровых фраз — названия причины и сравнения с когортой. Его ключ и нужные фразы сохранены; неиспользуемая часть с farewell/share/feedback и кнопками старого экрана удалена на всех пяти языках. Все десять результатов извлечения фраз до/после совпадают побайтно. Это внутренний перевод, а не загрузка старого экрана. Полный объём дополнительной очистки — 151 483 байта исходников; детали фиксируются в отчёте.

## Что намеренно осталось

| Остаточное упоминание | Зачем оно нужно | Является ли зависимостью от сайта |
|---|---|---|
| Название игры в UI, HTML, палитрах и документах | Пользователь сохраняет название продукта | Нет |
| Ключи `one8b.*`, `1in8b-mobile/v1:`, формат replay | Совместимость профиля, архива и журналов команд | Нет |
| `CORE_META.sourceSha256`, исходная версия в локальной диагностике | Идентичность исторической логики, совместимый replay и разбор ошибок | Нет |
| Исторические строки и исходные хеши в тестовых fixtures | Независимая проверка результатов | Нет |
| Запрещённые адреса в отрицательных тестах защитной проверки | Проверка, что такие адреса будут отвергнуты | Нет |
| Запрет `reference` в настройках dev-сервера | Защита от случайной раздачи подобных файлов | Нет |
| `tools/verification/` с явно передаваемым архивом | Необязательное сравнение для разработки | Только при отдельном явном запуске этого инструмента |
| Уведомления, исторические отчёты и сведения о происхождении | Документирование использованного кода, данных и материалов | Нет |
| Старые файлы в истории Git и резервной ветке | Возврат к прежней версии | Нет для текущей сборки |

Следовательно, утверждение «вообще нигде не осталось упоминаний источника» неверно. Проверяемый результат — отсутствие технического обращения к оригинальной игре и удаления ненужных сервисных материалов из текущего runtime. Код симуляции остаётся выделенным производным кодом с сохранённым происхождением.

## GitHub

Текущий корень репозитория обновляется исходниками локального движка и прежнего мобильного UI. Старое встроенное дерево `reference/` и генераторы удаляются из текущего коммита; запуск по новому README использует только текущие файлы. Уведомления используемых материалов сохраняются. История Git не переписывается.

Публикация проверяется теми же командами в CI, а существующий workflow GitHub Pages сохраняет ветку `release`. Полный порядок, совместимость хранилища и возврат описаны в `github-migration.md`.
