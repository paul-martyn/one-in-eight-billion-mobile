# Журнал команд одной жизни (`1in8b-replay/1`)

Журнал записывает команды одной жизни для регрессий, отчётов об ошибках и сверки будущей Unity-реализации. Адаптер ведёт его с момента рождения: `GameAdapter.exportReplay()`. Инструмент воспроизведения использует собственные локальные модули `src/engine/` и не требует внешнего снимка. Если жизнь загружена из сохранения посреди игры, журнала этой сессии нет: запись не начинается с рождения.

Формат унаследован от мобильной версии 1 ноября 2026 года. Исходный документ и его SHA-256 зафиксированы в [описи документации](documentation-import-2026-11-02.json). Ниже показана структура; пример команд не является готовой воспроизводимой fixture.

```json
{
  "format": "1in8b-replay/1",
  "core": "f98bd80cd361531ffcf27a660b7ea2706af0dbd9d0a56217e61c41c7967effb5",
  "generator": "standalone-engine/1",
  "entropy": -1234567890,
  "prefs": { "mode": "birth", "pace": 30 },
  "stepSeconds": 0.016666666666666666,
  "commands": [
    { "step": 0, "at": 1793525400000, "cmd": "startLife", "args": [] },
    { "step": 0, "at": 1793525407000, "cmd": "revealCertificate", "args": [] },
    { "step": 0, "at": 1793525416000, "cmd": "beginLife", "args": [] },
    { "step": 812, "at": 1793525420000, "cmd": "choose", "args": ["temper", "act", ""] },
    { "step": 2400, "at": 1793525460000, "cmd": "setFocus", "args": ["study"] }
  ],
  "endStep": 160532
}
```

| Поле | Значение |
|---|---|
| `core` | `CORE_META.sourceSha256` языкового модуля: сохранённый SHA-256 его исходной опубликованной сборки. Player выбирает один из пяти локальных модулей по этому полю; неизвестный хеш отклоняется |
| `generator` | Происхождение исполняемого модуля, сейчас `standalone-engine/1`. Сохраняется для диагностики; текущий player не использует его как отдельный критерий допуска |
| `entropy` | 32-битное состояние `Math.random` ядра в момент `startLife` (алгоритм `seedRng` оригинала). Поток сопутствующих жизней выводится из него: `state ^ 0x5bd1e995` |
| `prefs` | Снимок `UI.prefs` перед рождением: режим, темп, эпоха и прочие сохранённые настройки. Перед жизнью прошлого/будущего загружается локальная ERA |
| `stepSeconds` | длина одного шага времени (1/60 с реального времени) |
| `commands[].step` | сколько шагов времени выполнено с рождения до команды. Шаги идут только во время игры: пауза и открытое решение их не считают |
| `commands[].at` | время часов (мс эпохи) в момент команды; влияет на `S.by`, `S.td`, `S.startedAt` |
| `commands[].cmd`, `args` | Тип команды адаптера и её сериализуемые аргументы; полный список ниже |
| `endStep` | шаги после последней команды до момента выгрузки |

## Команды и воспроизведение

Player поддерживает:

- Рождение и решения: `startLife`, `revealCertificate`, `beginLife`, `choose [decisionId, key, note]`.
- Время и фокус: `togglePause`, `setPaused [bool]`, `setSpeed [n]`, `toggleFastForward`, `setFocus [key]`, `skipToEnd`.
- Покупки и настройки: `openSpend`, `buy [key]`, `setGift [value]`, `setDiet [value]`, `toggleHabit [key]`, `setInsurance [value]`, `setSurname [value]`, `setInvest [value]`.

```powershell
node --experimental-strip-types tools/harness/replay.mjs replay.json
```

Команда печатает фазу, возраст, число решений и SHA-256 итогового `S`. [replay.mjs](../tools/harness/replay.mjs) создаёт новый профиль в памяти, восстанавливает RNG и prefs, затем применяет команды тем же адаптером. `buy` воспроизводит и саму попытку покупки; неуспешная попытка не становится покупкой только из-за наличия записи. `skipToEnd` выполняет автоматическое доживание, а не подставляет готовый итог.

Тесты [adapter.test.mjs](../tests/core/adapter.test.mjs) и [spend.test.mjs](../tests/core/spend.test.mjs) записывают полные жизни с решениями, фокусом, скоростью, паузами, покупками и настройками, затем сравнивают точные итоговые состояния. Переключение языка или валюты завершает текущий журнал. Выбор вкладки, анимации, Claim и прочие операции мета-экономики не описываются этим форматом.

## Совместимость и известные ограничения

`sourceSha256` намеренно сохраняет идентификатор исторической языковой сборки, а не является хешем нынешнего выделенного файла. Поэтому английский идентификатор выше остался тем же при переходе от прежней обёртки к самостоятельному движку. Ранее записанные журналы могут содержать `generator: "extract-core/1"`; само это поле сейчас не блокирует загрузку. Это не доказывает совместимость любого старого журнала с любой будущей правкой движка: её нужно подтверждать поведением. Происхождение и реальные хеши проверенной реализации находятся в [описании движка](independent-engine.md) и [отчёте проверок](verification-summary.json).

Replay v1 не содержит полный исходный профиль: историю предыдущих жизней, всё хранилище и межжизненную память. Player начинает с записанных RNG и prefs. Поэтому **вторая и последующие жизни могут воспроизводиться иначе**, хотя идентификатор core и команды совпадают. В текущих тестах доказаны перечисленные сценарии, а не универсальная корректность replay после любой истории профиля. Это отдельный известный хвост; исправление требует полной начальной описи состояния или следующей версии формата, а не обновления ожидаемых хешей.

Язык определяется исходным хешем, неизвестные format/core/длина шага или неизвестная команда отклоняются. Значения `generator` и исходного хеша не заменяют проверку фактического результата `S`.

Для Unity те же команды, порядок, шаги и полное начальное состояние должны давать тот же `S`. Сравнивайте JSON после каждой команды; при межжизненных сценариях сначала нужно устранить ограничение начальной памяти. Текущий формат и JavaScript сами по себе не превращаются в C# автоматически.
