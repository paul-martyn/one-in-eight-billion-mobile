# Производный core: происхождение и технические изменения

Обновлено 1 ноября 2026. Эталон — `reference/original-0.8.98/src/game.en.js` (0.8.98 beta, SHA-256 `f98bd80c…effb5`) и `era.js`. Номера строк ниже относятся к этому файлу.

## Как получается

`npm run core:extract` (`tools/core/extract-core.mjs`) читает эталон, сверяет размер и SHA-256 с `reference/provenance.json` и записывает в `src/core/generated/` (каталог не хранится в Git):

| Файл | Содержание |
|---|---|
| `game.en.core.js` | `export function instantiateCore(env)` — внутри **побайтно неизменённое** тело `game.en.js`, перед ним привязка свободных имён к `env.globals`, после него таблица доступа `top` к 6 835 верхнеуровневым объявлениям |
| `game.en.core.meta.json` | версия генератора, SHA-256 источника, классификация 76 свободных имён |
| `era.core.js` | `export const ERA` — неизменённое тело `era.js` |

`npm run dev`, `npm run build` и `npm run check` запускают генерацию сами. `node tools/core/extract-core.mjs --check` подтверждает, что файлы соответствуют эталону и генератору.

Генератор разбирает сборку собственным анализом областей видимости (`tools/core/scope.mjs`, acorn 8.15.0) и отказывается работать, если:
- сборка несовместима со strict mode (ES-модуль);
- есть объявления функций внутри блоков (Annex B), верхнеуровневый `this` или присваивания необъявленным именам.

Для 0.8.98 все условия выполнены: 76 свободных имён, все только читаются.

## Локализованные сборки (1 ноября 2026)

Дополнительно генерируются `game.ru/es/fr/de.core.js` и метаданные. Русский берётся из существующего неизменяемого эталона; испанский, французский и немецкий — из отдельного нового снимка `reference/locales-0.8.98/`, сверяемого с `reference/locales-provenance.json`. Обёртка та же, тело каждой сборки не меняется. Загрузчик выбирает язык ленивым импортом.

Чтобы язык не создавал отдельный профиль, хранилище core отображает ключи `one8b.<lang>.(save|lives|past|unlived).*` в прежнее пространство `one8b.en.*`. Формат сохранения не меняется. При переключении передаётся тот же `S`, RNG и номер свидетельства, без повторного рендера или восстановления; ставится пауза и снимается ускорение. Подробности и ограничение старых текстовых записей — [локализация](localization.md). Полная жизнь каждой языковой обёртки сравнивается со своей неизменённой сборкой в `tests/core/localization.test.mjs`.

## Окружение (`src/core/env.ts`)

### Русская редактура словаря

`src/core/localization/ru.ts` содержит пять точечных поправок возраста начала пенсии: «в 61 год», «с 61 года», «в 62 года» вместо неизменяемого «61 лет». `createHost` устанавливает их в `I18N_T` сразу после создания русского экземпляра, до начала жизни и первого обращения к этим шаблонам. Используется штатная грамматика `L` / `ruFill`; формулы, RNG, команды и формат сохранений не меняются. Исходный снимок, генератор и тело производной сборки остаются прежними. Уже сохранённые записи не переписываются. Другие языки получают исходный словарь.

`tests/core/russian-localization.test.mjs` проверяет реальные шаблоны `L` на разных возрастах, английский текст и отсутствие расхода RNG. Прежние проверки эквивалентности по-прежнему сравнивают неизменённые тела сборок с их источниками; исключения для текстовых различий в них не добавляются.

| Группа | Имена | Что получает core |
|---|---|---|
| Встроенные JS | `Array, Object, JSON, Map, Set, Intl, …` (22) | те же объекты realm без изменений |
| Управляемые | `Math, Date, performance, setTimeout/Interval, requestAnimationFrame, crypto` | `Math.random` и `crypto` — поток `CoreEntropy`; `Date()` и `Date.now()` — часы хоста; таймеры — очередь `CoreTimers`, выполняется хостом; `requestAnimationFrame` старого цикла не используется |
| Хост | `window, document, localStorage, location, navigator, history, matchMedia, fetch, …` | инертный документ, хранилище с префиксом `1in8b-mobile/v1:`, `location` = `http://localhost/en/`, сеть закрыта (попытки записываются), `matchMedia('(prefers-reduced-motion: reduce)')` = true |
| Поздние | `ERA` и 11 таблиц других языковых сборок | изменяемые привязки; `ERA` подставляется загрузчиком по запросу `eraLoad()` |

Свойства, которые влияют на игру и заданы явно:
- `location.hostname = localhost`. Хост входит в список оригинала, поэтому нет пометки «неофициальный сайт»; `STATS_ON = false`, аналитика и серверные функции не включаются.
- `navigator.globalPrivacyControl = true`, `doNotTrack = '1'`.
- `navigator.languages = ['en']`. Часовой пояс берётся из `Intl` устройства, как у оригинала; он влияет на валюту по умолчанию (`CUR_TZ`) и на текст горячих линий.
- `matchMedia(prefers-reduced-motion)` всегда true. Старый интерфейс не показывается, поэтому для него движение всегда сокращено. Благодаря этому `startNewLife` идёт по своей штатной ветке без 25 декоративных `wpick` рулетки (199845). Новый интерфейс имеет собственную настройку движения.

## Загрузка без старого интерфейса

Последняя инструкция сборки (210312) вызывает `window.claude.hot.ready(start)`, если такой хост существует. Окружение передаёт `ready`, который **не вызывает** `start`. Старый UI не загружается и не подключается через iframe.

При загрузке оригинал ставит три таймера своего интерфейса: `cmBare` ×2 и `restTick` (напоминание об отдыхе). Хост снимает их сразу после создания экземпляра (`discardedBootTimers`). Задачи, поставленные позже командами (ломтики сопутствующих жизней), выполняются.

Идентификатор сессии аналитики `SID` (198256) при загрузке один раз берёт `Math.random`. Это число берётся из источника представления, а не из игрового потока. Иначе перезагрузка сдвигала бы поток.

## Случайность

- `src/core/entropy.ts`: `Math.random` ядра — генератор с алгоритмом `seedRng` оригинала (55668) и открытым 32-битным состоянием. Тест подтверждает совпадение последовательности с `seedRng`.
- `setRng` не вызывается: как в браузерной игре, `rnd()` берёт числа из `Math.random`.
- Состояние потока сохраняется под `mobile.entropy` при каждой записи core в хранилище. Тест проверяет, что жизнь после «перезагрузки» продолжается побайтно так же, как без неё.
- **Сопутствующие жизни** (`makeCompanionsSoon`) получают отдельный поток через штатный параметр `rng`, которым пользуется режим класса оригинала (199806-199832). В обычной браузерной игре они делят поток с основной жизнью. Тогда порядок чисел зависит от того, как ломтики по 12 мс чередуются с кадрами, и воспроизвести его нельзя. Отличие сознательное: основная жизнь не зависит от скорости устройства.

## renderAll и песочница чтений

В браузере `renderAll` (202917) не только рисует, но и меняет игру. Он лениво разыгрывает возраст смерти братьев и сестёр (`sibDA`), работу партнёра (`partnerJobFor`), домашний язык (`homeTongue`) и город учёбы (`studyCity`), а также записывает мемо-поля (`S.skn`). Эксперимент исследования показал, что даже 3 лишних числа меняют всю жизнь.

Поэтому адаптер вызывает **оригинальный `renderAll()`** в тех же точках, что браузерная игра: после `beginLife`, после каждого выбора (`pickChoice`), в кадре при смене возраста или флаге изменений (`frame0`). Документ при этом инертный: элементы принимают запись, `canvas` рисует в пустоту, вывод выбрасывается. Тест сверяет эти вызовы с исходными обработчиками и проверяет, что ошибок рендера нет.

Данные для новых экранов читаются только через `CoreHost.read()`. Внутри работает копия `S`, собственные `rndF` и `Math.random`, а запись в хранилище запрещена. После чтения восстанавливаются все 102 верхнеуровневых `let` ядра (`S`, `RND_N`, `rndF`, кэши, состояние последнего действия), поля объекта `UI` и кольцевой буфер последних переводов `L_RT/L_RS` (его читает строка «темы дня» в журнале, 151302). Тест «полная жизнь через адаптер» сравнивает жизнь, в которой экраны строились после каждого изменения, с той же жизнью без единого чтения. Результат совпадает побайтно.

## Лист «Spend & invest»

Оригинал строит список пунктов функцией `shopItems()` при каждой отрисовке листа. Эта функция тратит 3–5 чисел игрового потока на варианты хобби (`newHobOK` → `hobbyOptions`). Новый интерфейс строит список в песочнице, чтобы открытие вкладки не тратило игровой RNG. Это прямое требование к новому UI.

Покупка (`buy`) выполняется на настоящем `S` тем же путём, что обработчик `data-buy` (208322): `buyShop` сам проверяет доступность и варианты (`ok`, `lock`, `opts`, `optOK`, оплату), пишет результат в журнал, вызывает `renderAll` и `save`. Не повторяется только перерисовка листа после покупки, то есть её 3–5 декоративных чисел. Изменяющая часть `openShop` повторена командой `openSpend`: `S.ff = false` и флаг `shopSeen` в настройках. Подтверждение рискованных пунктов (двойное нажатие `shopAsk`, список `SHOP_ASK`) новый UI показывает окном с тем же текстом оригинала.

Подписи листа, настроек образа жизни и подтверждений берутся из словаря оригинала: `L` вызывается с тем же корейским шаблоном, что в `openShop`.

## Настройки следующей жизни

Экран Settings записывает те же `UI.prefs`, что стартовый экран оригинала: `mode` (по рождениям или по населению), `era`, `eraAny`, `eraY` и `pace`. Отличие: по решению продукта темп — 10 или 30 минут вместо 30/60/90. Сохранённый темп вне этого набора заменяется на 30 при загрузке. `newLife` ограничивает длину года 12–120 секундами (62702). Поэтому при темпе 10 минут жизнь длиной в ожидаемую продолжительность идёт 12–17 минут на скорости ×1. Формула не менялась.

## Мобильная мета-экономика

Энергия, доллары и кристаллы (`src/adapters/meta.ts`) — новый слой мобильной версии вне core. Новая жизнь стоит 1 энергии, на старте и максимум — 5. Пока энергии меньше максимума, раз в 30 минут добавляется 1; это временное значение до решения продукта. Состояние хранится под `mobile.meta.v1` и не влияет на симуляцию и её поток случайности.

**Награда за прожитую жизнь** («A life lived» в хабе, макет v107). В момент перехода жизни в фазу `dead` адаптер один раз строит награду в песочнице чтений (`src/adapters/vm/rewards.ts`) и кладёт её в мета-слой как ожидающую. Награда только читает итог жизни из core:

| Пункт | Условие в core | Сумма (макет v107) |
|---|---|---|
| Окончил школу | `S.edu >= 3` (таблица `EDU`, 52985), подпись — название уровня | 60 $ |
| Первая работа | наём был (`S.stats.jobs > 0`, 92975); подпись — первая годовая отметка `S.years[].w` (`yearWork`, 113025), которая не учёба, служба, поиск работы, пенсия или домашнее хозяйство | 40 $ |
| Брак | `S.fam.marriages > 0` или `S.fam.marriedAt` | 50 $ |
| Расплатился с долгами | был год с `nw < 0`, к концу `netWorth() >= 0` | 100 $ |
| Первая жизнь в этой стране | в архиве `LIVES_KEY` (уже с этой жизнью) ровно одна запись с этой страной | 2 кристалла |

Суммы взяты из примера в макете и ждут утверждения (`REWARD_RULES`). Награда хранится до нажатия Claim и переживает перезагрузку; повторно за ту же жизнь (`lifeAt`) не выдаётся. Claim зачисляет доллары и кристаллы и увеличивает счётчик новых жизней для бейджа вкладки Lives; открытие вкладки его сбрасывает.

## Skip to the end

Кнопка окна паузы (макет v107). Оригинал такой кнопки не имеет, но имеет штатный авто-режим: решения отвечает `autoChoice`, а выбор применяется как `pickChoice(k, true)` (`stats.auto++`, отметка `au=1`, `renderAll`, `save`). Команда `skipToEnd` повторяет этот путь: пока жизнь не закончилась, ответ на открытое решение — `autoAnswer`, иначе снимается пауза, включается «до следующего решения» (`S.ff = true`) и время идёт обычными шагами `frame0` по 1/60 с. Формулы, порядок RNG и события те же, что при игре без вмешательства игрока с авто-решениями. Работа идёт порциями по ~12 мс между кадрами, чтобы интерфейс оставался отзывчивым; на это время остальные команды отклоняются (`snapshot.skipping`). В журнале повторов команда записывается одной строкой `skipToEnd`, и повтор даёт ту же жизнь (тест «Skip to the end, награда за жизнь и Claim»).

## Время

`tick` обрабатывает очередь событий по долям года. Порядок событий и чисел не зависит от нарезки `dt`. Исключение — `S.fT` фокуса: в нём учитывается весь шаг до обработки очереди (71555). Поэтому адаптер передаёт время шагами фиксированной длины 1/60 с реального времени, как кадры 60 Гц. Исход не зависит от частоты кадров устройства. Ограничение кадра 0,25 с и множитель ×24 для «до следующего решения» взяты из `frame0`.

Время идёт только пока открыт экран жизни (вкладка Life), нет окна результата решения и вкладка браузера видима. В оригинале время так же останавливалось, когда был открыт любой лист (`$('#sheet').hidden`). Вкладки People, Activities, Money, Odds работают как такие листы. Отличие: окно результата решения держит время до нажатия Continue, а оригинал продолжал сразу после выбора.

## Сохранения

Формат — оригинальный конверт `{S, at}` под `one8b.en.save.v3` в пространстве `1in8b-mobile/v1:`. Запись делает сам `save()` оригинала: в конце года, после решений, при паузе, при скрытии вкладки и `pagehide`. Восстановление повторяет `restore0`: `ff = false`, `healStats`, `ageSync`, `renderAll`. Жизнь продолжается на паузе, как `resumeLive`. Миграций интерфейсной модели нет, сохранение никогда не сбрасывается.

## Известные открытые вопросы

- Сравнение с оригиналом выполнено в V8 (Node 24, Chromium). Возможные различия последнего бита `Math.pow/exp/log` в JavaScriptCore (Safari) не проверены.
- Валюта по умолчанию зависит от часового пояса устройства, как в оригинале. Явный выбор валюты (`one8b.cur.en`) требует экрана настроек и перезапуска экземпляра core, как перезагрузка страницы в оригинале.
- Русская сборка `game.ru.js` пока не генерируется: генератор поддерживает её добавлением языка в список.
