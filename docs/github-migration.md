# Переход на локальный движок

Подготовлено 2 ноября 2026 года. База изменения — `develop`, коммит `9a7e2517490b1cc7e7d4d8ee4e2186fb6a739ac5`. Ветка подготовки — `codex/standalone-engine`.

Тот же базовый коммит сохранён на GitHub как [codex/generated-core-fallback-2026-11-02](https://github.com/paul-martyn/one-in-eight-billion-mobile/tree/codex/generated-core-fallback-2026-11-02). Эта ветка сохраняет прежнее состояние GitHub; полный локальный ZIP дополнительно содержит незакоммиченные правки и проверки рабочей версии.

## Что меняется

Вместо генерации полного bundle из встроенного снимка приложение импортирует проверенные исходники `src/engine/`. Папка `reference/`, генератор `tools/core/` и загрузчики оригинальной страницы уходят из текущего дерева Git. Их история остаётся в прежних коммитах. Локальная рабочая мобильная версия и её полный проверенный ZIP сохранены отдельно от этого каталога.

Мобильный интерфейс, порядок команд, формулы, игровые данные и совместимые ключи сохранений сохраняются. Отдельно исправлена подготовка данных эпохи перед восстановлением и сменой языка/валюты. Аналитика, облако, платежи и социальный сервер не подменяются другими сервисами.

Неиспользуемые старые инструкции генерации и интеграционный промпт заменены актуальной архитектурой и описанием тестов. Карта экранов, параметры движения, локализация и формат replay перенесены как документы текущего продукта. Происхождение, исходные хеши и уведомления остаются документированными.

## Проверка и публикация

`CI` проверяет pull request в `develop`, `release` или `master`, а также push в эти ветки:

```text
npm ci
npm run check
npm run build
npm run verify:build
```

Ни один из этих шагов не скачивает исходную игру и не ищет соседний проект. Интернет нужен `npm ci` для установленных в lockfile npm-пакетов; движок после установки работает локально. Опциональная сверка `test:oracle` принимает только явно указанный архив и не запускается в CI.

Workflow `Pages` сохраняет публикацию из `release` и проверяет сборку перед загрузкой `dist`. Pull request сам по себе не меняет опубликованный сайт. Ветки `develop`, `release` и `master` не следует перемещать принудительно: перенос выполняется обычным merge после проверки соответствующего коммита.

## Сохранения и возврат

Сохранены ключи `one8b.*`, префикс `1in8b-mobile/v1:`, формат жизни `{S, at}`, идентификаторы replay и исходная совместимая идентичность движка. Эта часть намеренно не переименовывается ради косметической очистки.

При публикации на прежний origin новое приложение читает тот же профиль. Другой путь GitHub Pages не изолирует localStorage: два проекта под `paul-martyn.github.io` делят его. Для параллельной проверки используйте отдельный origin/профиль; порты разработки 4190 и 4192 уже различаются.

Текущий переход не очищает браузерные сохранения и не запускает массовую миграцию данных. Для возврата можно заново опубликовать прежний коммит `release` или восстановить проверенную резервную копию. Опубликованный код и браузерное сохранение — разные объекты: резервная копия исходников не заменяет экспорт пользовательского прогресса.

В репозитории не выполняется переписывание истории. Поэтому старые названия, снимки и сведения об источнике остаются доступны в исторических коммитах даже после удаления из текущего дерева.
